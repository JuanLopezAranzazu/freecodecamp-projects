Getting Started

Git is a distributed version control system that allows developers to track changes in their projects and collaborate with other people.

Before using Git, you should install it on your computer and configure your identity with your name and email address.

A new Git repository can be created inside an existing project using the git init command. 

git init
  • Install Git on your operating system.
  • Configure your Git username.
  • Configure your Git email address.
Repositories

A repository contains all the files, history, branches, and configuration information associated with a project.

Repositories can exist locally on your computer or remotely on platforms such as GitHub.

You can copy an existing remote repository to your computer using the git clone command. 

git clone https://github.com/user/project.git
  • Local repositories are stored on your computer.
  • Remote repositories allow collaboration.
  • GitHub can host Git repositories online.
Branches

Branches allow developers to work on different versions of a project without modifying the main branch directly.

A common workflow is to create a feature branch, make changes, and later merge those changes into the main branch.

The following command creates a new branch and switches to it: git switch -c feature-login. 

git switch -c feature-login
  • Branches isolate new development work.
  • The main branch usually contains stable code.
  • Branches can be merged after development is complete.
Commits

A commit represents a saved snapshot of changes in a Git repository.

Before creating a commit, files are normally added to the staging area using the git add command. 

git add .

After staging the changes, use git commit with a descriptive message. 

git commit -m "Add login form"
  • Keep commits focused on a specific change.
  • Write clear and meaningful commit messages.
  • Review your changes before committing them.
Pull Requests

A pull request is a proposal to merge changes from one branch into another branch, commonly used when working with GitHub.

Pull requests allow team members to review code, discuss changes, and identify possible problems before merging.

A typical workflow involves pushing your branch to a remote repository and then opening a pull request. 

git push origin feature-login
  • Create a branch for your changes.
  • Push the branch to the remote repository.
  • Open a pull request for code review.
  • Address review comments.
Useful Commands

Git provides many commands for inspecting and managing the current state of a repository.

The git status command displays modified, staged, and untracked files. 

git status

You can inspect previous commits using git log. 

git log --oneline
  • git status — View repository changes.
  • git add — Stage files.
  • git commit — Create a commit.
  • git pull — Download remote changes.
  • git push — Upload local commits.
